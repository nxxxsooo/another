## OpenCode command ownership and API boundary

- Live inventory lists `another.sessions` active with server and TUI features.
- An owned scratch TUI probe inspected the actual public keymap API and found
  exactly **one** `/ref`: `another.sessions.ref`, palette enabled through the
  normal integration and slash arguments enabled. Invoking it with `hc keys`
  opened `Reference / watch`; Escape cancelled it. The owned terminal/location
  was removed, with no session created.
- The requested `GET /api/command` check returned **zero** `ref` entries: that
  endpoint inventories server commands, not client-local TUI keymap commands.
  This is a verification-method limitation, not a missing slash command. No
  fake server command was added merely to change the count.
- The daily plugin deliberately uses the released binary. The independent MCP
  registration remains on `another-dev` as requested; refreshing dev from main
  does not reinstall the plugin or alter that entry. Consequently an aggregate
  recall-adapter status can regard the MCP executable name as outdated relative
  to the released installer, even while the sessions bundle itself is current.

## Known limitations

- Native Windows Go/Node behaviour passed CI; live Windows/Linux OpenCode TUI
  reference/watch interactions were not exercised. macOS live checks do not
  imply those native runtime scenarios passed.
- Watching covers the connected OpenCode server's events only. Standalone
  servers are separate, groups are server-instance-scoped, and watching does
  not expand MCP project scope. No Herdr watch backend or watch CLI remains.
- Cached full-text search only matches already-indexed content. Explicit
  refresh/rebuild bypasses remote discovery failure backoff; failed scans do
  not delete cached rows. Bounded recall excludes pure notification turns,
  while full export/migration/show preserve their existing behaviour.
- Interactive-shell verification removed terminal-proxy detection variables
  only in that subprocess after raw-mode initialization failed without a TTY.
  No shell configuration was changed or checks bypassed.
