# v0.24.2 — release verification

Released on 2026-11-07 as a patch release. Moving an OpenCode V2 session that
was mid-turn reported "OpenCode V2 refused the move" although the move landed
moments later: OpenCode V2 takes a move for a busy session into the session
inbox (`session_inbox`, type `move`, delivery `steer`) and applies it at the
next step boundary, while another waited only two seconds for the directory to
change. A move to the requested directory still waiting in the inbox is now
reported as queued in the CLI and the TUI; anything else is still a refusal.

## Regression and runtime checks

- Full Go test suite, `go vet`, and `gofmt` passed locally; native Windows ran
  in CI.
- New tests: a move queued in the inbox for the requested directory returns
  `Moved` and `Pending` without error; a move queued for a different directory
  is still reported as refused; the TUI status names the queued move in English
  and Chinese.
- End to end against OpenCode 2.2.5: a probe session made busy by a running
  turn was relocated with the built CLI, which printed the queued message; the
  directory changed once the turn ended. An idle session's move landed in under
  0.1 s, as before. The probe session was deleted afterwards.
- Only the OpenCode V2 move path and relocate reporting changed; Pi relocation
  and the other providers are covered by the unchanged suites in CI.
