# v0.25.0 — release verification

Released on 2026-11-09 as a minor release adding the opt-in Doubao provider
for shared desktop Work and CLI conversations, plus event-triggered automatic
native titles on macOS. The listener reacts to native completed-turn logs,
applies the existing title policy, and writes titles back through Doubao's
native API; it does not run a periodic scan.

## Regression and runtime checks

- PR and `main` CI: full Go suite, race suite, `go vet`, `golangci-lint run ./...` (0 issues), and the Windows race suite all passed.
- `goreleaser check` passed before tagging; release automation completed successfully.
- Dev live verification: a new desktop Work conversation and a new CLI conversation both changed from `测试` to `1109｜Explore｜Conversation Test` without a manual refresh or rename command; the native API, `doubao --list`, and the desktop window title all read back the new name. A later cross-client no-op event left the title unchanged.
- Desktop first-turn events use `conversation_type=5` and `chat_scene=generic_start_page_new_conversation`; the parser accepts this shape as well as the resumed `type=3/normal_conversation` duplicate. A regression test covers both.
- Listener verification: launchd runs `title-policy doubao --watch` with no `StartInterval`; idle CPU was 0.0%, no idle TCP sockets, and about 1.65k watched log FDs under the raised 16,384 limit.
- Native Windows/Linux Doubao authentication was not tested and is not supported; Windows CI covers build, tests, race tests, and shell validation only. The event listener is macOS-only.
- The event source is observed native log telemetry rather than a documented public hook; a future Doubao release can change the record shape.
