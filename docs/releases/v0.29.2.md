# v0.29.2 — release verification

OpenCode 2.4 no longer drops the `another` MCP server at startup. The server
advertises only handshake-era protocol versions, so OpenCode's
`server/discover` probe is rejected and the client completes `initialize`.

| Surface | Verification |
| --- | --- |

A new regression test sends `server/discover` then `initialize` on one
connection; it failed before the fix and passes after. The full Go suite,
vet and gofmt passed. Against live OpenCode 2.4.0 on macOS, the shared
server logged 14 `mcp connected` and no failures for `another` after the
fixed build was installed, where every earlier 2.4.0 start had logged
`duplicate "initialize" received`. OpenCode 2.4 on Linux and Windows, and
consumer installs on Linux and Windows, were not exercised.
